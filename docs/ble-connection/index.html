Подключение к Flipper Zero

Интерактивная блок-схема подключения Android-приложения: системное сопряжение, GATT-профиль, CCCD и проверка готовности RPC. Нажми на любой блок, чтобы раскрыть последовательность вызовов и обработку ошибок.

Android · KotlinBLE Serial ServiceGATT + RPC
ДВА УРОВНЯ ГОТОВНОСТИ
GATT ConnectedПрофиль проверен, CCCD настроены, можно получать уведомления.
RPC ActiveRPC_STATUS = ACTIVE; отправка дополнительно учитывает FLOW_CONTROL.

Состояние подключения и активность RPC хранятся отдельно. Они не взаимозаменяемы.

Алгоритм подключения

Основная последовательность и раскрывающиеся схемы внутри каждого блока. 0 из 8 раскрыто.

Поиск устройства

Находим устройство и получаем его Bluetooth-адрес.

startScan()Проверка доступности и разрешений
→
onScanResult()Имя, адрес и RSSI
→
BleDeviceПользователь выбирает устройство

Привязка к коду

BleConnectionRepository.startScan() → BleScanner.start(); stopScan() отменяет таймаут и сканирование.

Ошибки и остановка

BLUETOOTH_SCAN / BLUETOOTH_CONNECT, отключённый Bluetooth, неуспешный scan, системные службы геолокации на Android 11 и ниже.

Поиск не фильтруется только по стандартному имени Flipper: устройство может быть переименовано.

Сопряжение

Проверяем системную пару и при необходимости ждём bonding.

BOND_BONDED?Проверка bondState
→
createBond()Если устройство ещё не сопряжено
→
ACTION_BOND_STATE_CHANGEDПодтверждён BOND_BONDED

Привязка к коду

BlePairingManager → onPairingStarted() → onSuccessBonding(remote, device) → startGattConnection().

Ошибки и остановка

Отказ пользователя, BOND_NONE, потеря BLUETOOTH_CONNECT или таймаут ожидания 45 секунд → PairingFailed / TimedOut.

Для уже сопряжённого устройства createBond() не требуется. Отмена ожидания не обязательно останавливает системную процедуру bonding.

GATT-соединение

Создаём BluetoothGatt и устанавливаем LE-соединение.

connectGatt()TRANSPORT_LE, mainHandler
→
onConnectionStateChange()status == GATT_SUCCESS?
→
STATE_CONNECTEDЗапустить discovery

Привязка к коду

BleConnectionRepositoryImpl.startGattConnection(); currentGatt хранится на время активной сессии.

Ошибки и остановка

GATT error, disconnect либо таймаут подключения (25 секунд) → failGatt(), закрытие текущей GATT-сессии.

Callback старого соединения игнорируется через проверку isCurrentGatt(gatt).

Обнаружение сервисов

Убеждаемся, что Flipper предоставляет нужный Serial Service.

discoverServices()Асинхронный поиск GATT-сервисов
→
onServicesDiscovered()status == GATT_SUCCESS?
→
validateGattConnection()Service, четыре характеристики, CCCD

Привязка к коду

FlipperGattUuid.SERVICE; RX, TX, FLOW_CONTROL, RPC_STATUS; CCCD для трёх характеристик.

Ошибки и остановка

Ошибка discoverServices или отсутствие требуемых характеристик/CCCD → ServiceDiscoveryFailed / InvalidGattProfile.

Наличие GATT-соединения ещё не означает, что Serial Service проверен или уведомления настроены.

Подписка на характеристики

Записываем CCCD строго последовательно, дожидаясь callback.

TX · CCCDENABLE_INDICATION_VALUE
→
FLOW_CONTROL · CCCDENABLE_NOTIFICATION_VALUE
→
RPC_STATUS · CCCDENABLE_NOTIFICATION_VALUE

Привязка к коду

initSubscribingQueue() → processNextSubscription() → onDescriptorWrite(SUCCESS) → следующая характеристика.

Ошибки и остановка

Не удалось настроить локальные notifications / записать CCCD → EnableCCCDProblem.

После третьего успешного onDescriptorWrite() устанавливается BleConnectionState.Connected. Это готовность GATT, но не обязательно активная RPC-сессия.

Проверка RPC_STATUS

Определяем, активен ли RPC на Flipper.

readRpcStatus()Начальное чтение RPC_STATUS
→
onCharacteristicRead()Чтение завершено · saveRpcState()
→
readFlowControl()Следующая GATT-операция

Привязка к коду

saveRpcState(RpcStatus.ACTIVE | NOT_ACTIVE); FlipperBleSender.awaitRpcActive() ждёт активности RPC перед отправкой.

Ошибки и остановка

Неудачное чтение → RPCReadError. Некорректный payload не должен автоматически трактоваться как ACTIVE.

NOT_ACTIVE не равно разрыву Bluetooth: GATT может оставаться Connected. onCharacteristicChanged(RPC_STATUS) только обновляет статус через saveRpcState() и не вызывает readFlowControl(). Следующее чтение FLOW_CONTROL запускается из onCharacteristicRead(RPC_STATUS) после завершения первоначального чтения.

Инициализация FLOW_CONTROL

Получаем первоначальное окно отправки и обновления кредита.

readFlowControl()После onCharacteristicRead(RPC_STATUS)
→
onCharacteristicRead()Начальное значение · big-endian
→
onCharacteristicChanged()Новые окна по notify

Привязка к коду

handleFlowControlValue(value) → FlipperBleSender.setAvailableBytes(available); значение декодируется из 4 байт в порядке BIG_ENDIAN.

Ошибки и остановка

Ошибка чтения или неверный размер payload → RPCReadError; при нулевом кредите отправитель ожидает новое окно.

Начальное чтение FLOW_CONTROL инициируется после успешного завершения чтения RPC_STATUS. Последующие onCharacteristicChanged(FLOW_CONTROL) обновляют доступное окно через setAvailableBytes(), не запускают GATT-чтение и не прибавляют значение к прежнему остатку.

Передача данных

После проверки условий можно обмениваться байтами.

awaitRpcActive()Сессия должна быть ACTIVE
→
sendRxMessage(message)MTU · RX ≤ 486 · credit · Mutex
→
onCharacteristicWrite()Подтверждение RX; TX → receiver

Привязка к коду

FlipperBleSender.sendRxMessage() → writeRxChunk() → BluetoothGattCallback.onCharacteristicWrite() → FlipperBleSender.handleCharacteristicWrite(); TX → onCharacteristicChanged() → FlipperBleReceiver.onReceive().

Ошибки и остановка

Disconnect, NOT_ACTIVE, ошибка записи, таймаут или переполнение буфера приёма → прекращение отправки / сброс текущей передачи.

Это логическое условие готовности, а не новый публичный BleConnectionState. Готовность RPC нельзя определять только по Connected.

Отключение и восстановление

При disconnect или критической ошибке текущий GATT закрывается, значения RPC_STATUS и кредита отправки сбрасываются, поздние callback'и старой сессии игнорируются. Для нового подключения запускается новая последовательность.
